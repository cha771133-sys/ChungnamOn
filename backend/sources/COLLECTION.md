# 공식 HTML 수집 운영 (P1-7)

## 실행

프로젝트 가상환경에서 의존성을 설치하고 `backend/`에서 마이그레이션 후 실행한다.
SQLite·PostgreSQL 모두 같은 ORM과 URL 고유 제약을 사용한다.

```powershell
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py collect_sources --dry-run
python manage.py collect_sources --limit 3
python manage.py collect_sources --url "https://www.asan.go.kr/main/cms/?no=93"
```

`sources/data/source_urls.yaml`만 읽으며 목록 밖 URL 입력은 거부한다. 별도 목록 경로나
본문 선택자를 명령행에서 주입할 수 없다. URL 발견·사이트맵·재귀 탐색을 하지 않는다.
목록에서 제거하거나 비활성화해도 기존 자료·청크는 삭제하지 않는다.

`--limit`은 활성 URL 중 실제 시도할 개수를 제한한다. 전체에는 선택된 목록의 비활성 항목과
limit 초과 항목도 포함하며 이들은 건너뜀으로 집계한다. `--url`은 정규화 후 정확히 일치하는
등록 URL만 선택한다. `--dry-run`은 같은 네트워크·파싱·해시 비교를 수행하지만 자료와 로그를
모두 쓰지 않는다. 화면의 신규·갱신 수는 저장했을 경우의 예상 결과다.

전체·신규·갱신·동일·실패·건너뜀 수를 출력한다. 전체 성공은 종료 코드 0,
일부/전체 수집 실패와 잘못된 목록·옵션은 종료 코드 1이며 오류 문구로 구분한다.
일부 실패에도 나머지 URL 처리를 계속한다. 라이브러리 코드가 중단되면 이미 생성한 RUNNING
이력이 남으므로 운영자가 `CrawlLog`의 결과·시각을 확인한다. 별도 정리 스케줄러는 없다.

## 요청과 본문 검증

- HTTPS·기본 포트·정확한 공식 호스트 허용목록을 사용한다. HTTP 예외는 현재 없다.
- P1-6 URL 정규화를 재사용한다. 문서를 식별하는 쿼리와 순서를 보존하며 추적 파라미터도
  자동 삭제하지 않는다. 추적용이라는 사실을 개발자가 확인한 경우에만 목록에서 제거한다.
- URL 인증정보·민감한 쿼리 이름·IP 직접 입력을 거부한다. DNS의 모든 주소가 공인이어야
  하며 검증한 IP로 연결을 고정하고 원래 호스트의 Host·SNI·TLS 인증서 검증을 유지한다.
  환경 프록시는 사용하지 않아 프록시가 연결 검증을 우회하지 못한다.
- robots.txt를 먼저 확인하고 호스트별로 캐시한다. 404/410은 규칙 없음으로 처리하지만
  권한 오류·서버 오류·규칙 파싱 불가는 실패로 처리한다. 와일드카드·Allow는 Protego로 처리한다.
- 기본 호스트 간격 1초, Crawl-delay·Request-rate 중 더 긴 간격을 적용한다.
  연결/읽기 타임아웃은 5/15초, 스트림 읽기는 추가로 30초를 제한한다.
- 최초 요청 외 재시도는 최대 2회이며 일시적 연결 오류·429·500/502/503/504에만 적용한다.
  Retry-After를 존중한다. 60초를 넘는 대기 요구는 짧게 무시하지 않고 이번 실행을 실패 처리한다.
  403/404·TLS 오류는 반복하지 않으며 읽는 도중 끊긴 본문은 저장하지 않는다.
- 리다이렉트는 최대 3회이며 목적지의 호스트·DNS·robots도 다시 확인한다.
  응답 Content-Type과 선언 크기, 압축 해제한 실제 크기를 검사한다(HTML 2MiB, robots 256KiB).
- 한국어 UTF-8·CP949/EUC-KR, 명시된 charset을 엄격히 해석하며 깨진 문자·빈/짧은 본문,
  메뉴·로그인·오류 페이지는 성공 처리하지 않는다. 사이트별 선택자는 `parser.py`에 분리한다.
- 본문의 절차·기한·준비서류·연락처·표를 보존하고 공통 메뉴·팝업·푸터를 제거한다.
  표는 행마다 줄바꿈, 열마다 `|`, 병합 셀은 같은 행 그룹 안에서 각 해당 행/열에 반복한다.
  병합 셀을 펼친 표 전체와 최종 정제 원문은 각각 페이지당 2,097,152자로 제한한다.
  표는 확장 문자열을 만들기 전에 누적 길이를 검사하고, 초과하면 `BODY_TOO_LARGE`로
  해당 수집을 실패 처리하여 기존 정상 원문을 보존한다. 잘못된 링크는 주소만 제외하고 안내문은 보존한다.
- PDF/HWP/HWPX·OCR·브라우저 렌더링·로그인·CAPTCHA·접근 제한 우회는 지원하지 않는다.

## 저장·오류·AI 계약

URL·기관·지역·분류·검증된 날짜는 목록이 기준이다. 본문 제목은 실행 출력으로 남기고
목록 제목과 다르면 확인 필요로 표시한다. 본문 발행일을 추측하지 않으며 `published_at`의
null은 유지한다. `collected_at`은 HTML 확인·정제에 성공한 실제 시각이다.

새 URL은 ACTIVE로 저장한다. 동일 해시는 원문·해시 필드를 다시 쓰지 않고 메타데이터와
확인일만 갱신한다. 다른 해시는 같은 자료 행의 원문·해시를 함께 교체한다. 관리자에 의해
INACTIVE가 된 자료는 수집만으로 재활성화하지 않는다. 실패는 기존 자료를 전혀 수정하지 않는다.
URL UNIQUE와 행 잠금·get_or_create로 동시 중복 생성/부분 갱신을 막으며 오래된 확인 결과가
더 최근 결과를 덮어쓰지 않게 한다. SQLite에서는 쓰기 경합이 실패 이력으로 남을 수 있으며
해당 URL을 다시 실행한다. 실행 중 여러 프로세스를 스케줄링하는 기능은 제공하지 않는다.

실제 시도는 HTTP 요청 전에 RUNNING 이력을 만들고 완료 시 SUCCESS/FAILED와 종료 시각을
기록한다. 정상 자료와 SUCCESS 기록은 같은 트랜잭션에 확정하고, 실패 기록은 롤백 밖에서
남긴다. 로그 생성이 안 되면 추적 불가능한 요청을 보내지 않는다. 로그 종료까지 실패하면
RUNNING이 남을 수 있음을 출력한다. DB·네트워크·파싱 오류 코드를 구분하며 외부 예외 원문,
응답 전문·쿠키·토큰은 로그에 넣지 않는다.

후속 AI는 `SourceDocument.objects.values('id', 'source_url', 'status', 'content_text',
'content_hash', 'published_at', 'collected_at').get(pk=...)`로 원문 스냅샷을 한 번에 읽는다.
처리를 시작할 때 원문 해시를 작업 메타데이터에 보관하고, 결과를 적용하거나 근거로 제공하기
직전에 현재 원문 해시와 비교해야 한다. 해시가 바뀌거나 상태가 INACTIVE이면 새 원문의 최신
근거로 사용하지 않는다. **기존 SourceChunk에는 생성 당시 해시가 없으므로 최신성 미확인으로
취급한다.** 청크·임베딩은 원문 변경/실패/동일 확인 어느 경우에도 자동 삭제·재생성하지 않는다.
후속 AI의 해시 저장 위치·재처리 워커는 후속 이슈에서 정하며 P1-7은 임베딩 작업을 구현하지 않는다.
ACTIVE는 수집 결과를 사용할 수 있다는 관리 상태이며 정책의 현재 유효성·개인 적용을 보증하지 않는다.

## 2026-11-04 URL 검토

등록 6개 중 기본 활성 3개다. 숫자를 채우기 위한 검색 결과·가상 URL은 포함하지 않았다.
각 항목의 `notes`와 `enabled`를 함께 검토한다. 실제 서버의 HTML·본문과 robots를 확인했으며
접근이 허용된 공개 사실 안내만 수집한다. 외부 재배포·상업적 이용·AI 학습 허가를 포괄적으로

따라서 건강보험·충남도청 자료와 활성 URL 10~20개 목표는 아직 확보하지 못했다.
운영자가 공식 상세 페이지·최신성·정책을 검토한 뒤 YAML 변경 PR로 추가해야 한다.

## 테스트

자동 테스트는 수작업 HTML fixture와 HTTP/DNS mock만 사용하며 공식기관에 접속하지 않는다.
`python manage.py test sources` 또는 전체 `python manage.py test`로 실행한다.
실제 사이트 검증은 별도 임시 SQLite DB에 `migrate` 후 명령을 실행하여 구분한다.
실제 본문이 자연 변경될 수 있으므로 신규/동일/변경 수는 고정된 기대값으로 테스트하지 않는다.

본문 변경·네트워크/DB 실패·부분 실패 후 계속 처리는 외부 서버에 오류를 유발하지 않고
mock 기반 자동 테스트로 검증했다. 실제 내용 변경 또는 실제 수집 실패를 관찰했다고 주장하지 않는다.
